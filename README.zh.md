# brkpt-auth

[English](./README.md) | 简体中文

面向 NestJS 的透明、可组合、可移植的六边形架构身份验证方案。

---

## 设计理念

为项目添加身份验证，通常有四种常见做法，各有代价。

**托管服务**把身份验证做成一个托管 API，集成速度快。但数据库 schema、会话模型（传统 session、无状态 JWT 或有状态 JWT）、令牌传输方式（cookie 或 header）、JWT 载荷结构，全部由供应商决定，对你不可见，也无法调整；你还需要让渡数据主权，并承担供应商锁定的风险。

**自托管类库**以 npm 包的形式分发，运行在你自己的基础设施上，数据仍由你掌控。但核心设计依然固定且高度抽象：定制任何内容都需要先理解该库的内部模型，模型覆盖不到的需求，即便借助插件也难以甚至无法满足。代码虽以 `node_modules` 的形式存在于本地，但这并不会让内部实现更容易理解或修改。

**身份验证脚手架**提供完整源码，但代码是针对某一种特定的用户模型、数据库和项目结构设计的。与项目不符的部分，都需要自行修改。这类脚手架大多号称生产就绪、易于扩展，但实际在其基础上开发时，往往会暴露出耦合过紧、架构边界不清、结构冗余、可读性差、功能缺失等问题，且这些代码并非自己设计，排查问题也更困难。下一个项目又需要重新经历一次同样的评估与返工。

**完全自行开发**能给你完全的掌控权，代价是：没有统一的约定可用于检验实现是否合理，逻辑容易散落在代码库各处，部分能力难以干净地实现，一个新需求有时会引发一次较大的架构调整，而不只是一次较小的新增。每个新项目都需要从同样的基础重新开始。

## 为什么选择 brkpt-auth

brkpt-auth 将完整源码安装在你的项目中，通过端口与适配器分离业务逻辑与基础设施，使数据库 schema、用户模型和 JWT 载荷始终由你掌控：

- **透明** — 完整源码直接安装到你的项目中。没有编译产物，没有隐藏行为，结构清晰，便于检查和修改。
- **可组合** — 按需添加。各个功能相互独立，通过事件通信，耦合度低。
- **非侵入** — 不对你的数据库 schema、用户模型或 JWT 载荷做任何假设。实现所需的端口即可完成集成，不必重构应用。
- **可移植** — 业务逻辑与适配器相互独立。将身份验证逻辑迁移到另一个项目时，只需替换适配器。
- **NestJS 原生** — 从一开始就围绕 NestJS 的模块、依赖注入、守卫、装饰器和提供者构建。
- **六边形架构** — 服务承载业务逻辑，端口定义契约，适配器完全由你掌控。

上手很简单：`brkpt-cli` 将源码安装至你的项目中，你实现适配器并将其列入 `features.ts`；`BrkptAuthModule` 只需在 `AppModule` 中注册一次，之后会自动读取其中的内容。多数适配器方法都是简单的字段映射，或是对现有代码的直接调用。

## 功能列表

| 功能              | 说明                               |
| ----------------- | ---------------------------------- |
| `core`            | 无状态 JWT 双令牌认证。**必需**。  |
| `credentials`     | 账号密码注册与登录                 |
| `oauth`           | 社交账号登录                       |
| `otp`             | 一次性密码登录与验证               |
| `magic-link`      | magic link 登录与验证              |
| `session`         | 构建在无状态 JWT 之上的会话管理    |
| `blacklist`       | 实时撤销 access token              |
| `verify-email`    | 邮箱验证门禁，账号未验证前功能受限 |
| `change-password` | 已登录状态下修改密码               |
| `reset-password`  | 验证账户所有权后重置密码           |
| `audit`           | 为关键身份验证事件提供自定义处理器 |

## 仓库结构

```plain
brkpt-auth/
 ┣ demo/     # 完整可运行的 NestJS 示例项目
 ┗ lib/      # brkpt-cli 分发的源码模板
```

### 运行示例

将 `.env.example` 复制为 `.env` 并填入配置，然后：

```bash
cd demo
pnpm install
pnpm start:dev
```

示例项目使用内存用户存储，但需要一个本地 Redis 实例。E2E 测试将 Redis 与邮件均替换为内存模拟，因此不需要任何外部服务。

```bash
pnpm test        # 单元测试
pnpm test:e2e    # e2e 测试
```
